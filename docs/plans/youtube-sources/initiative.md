# YouTube sources

Goal: From each source's Choose audio button, open a popover to choose a local audio file or submit a YouTube URL. Extract audio on the server via yt-dlp and decode it in the existing browser source pipeline.

Non-goals: playlists, video playback, saving YouTube media, changing local-file persistence, or hosting/deployment changes.

Contract: POST `/api/youtube/audio` with JSON `{ "url": "https://www.youtube.com/watch?v=…" }`; success returns `audio/wav` bytes and the UTF-8 video title percent-encoded in `X-Source-Title`. Failures return JSON `{ "error": "…" }` with a non-2xx status. Only YouTube video URLs are accepted. The server runs yt-dlp and ffmpeg using pipes, with no media file or cache, bounded request/output/runtime. Browser never stores the downloaded audio in IndexedDB; it replaces the source PCM and clears any previously stored local file for that source. Source metadata retains the title and duration for layout restoration; no YouTube URL is stored.

Acceptance: Local import still works via the menu; a valid YouTube video URL loads playable PCM in the selected source and names it with the video's title; invalid/unavailable URLs expose a recoverable error without replacing existing audio; extracted media is only in transient process/browser memory and not written to persistent storage.

Verification: Server endpoint integration with controlled executables and process termination plus direct HTTP smoke; actual browser popover/local picker, keyboard and URL error recovery; build and tests; live YouTube extraction if external access permits.

Risks: Remote yt-dlp access may fail due to YouTube restrictions. Server needs installed `yt-dlp` and `ffmpeg` binaries in its runtime PATH; document this operational prerequisite. yt-dlp and ffmpeg are subprocesses, not shell commands, and must be bounded/cleaned on aborted requests.

## Video title propagation (2026-09-27)

`yt-dlp --print before_dl:…%(title)j -o -` emitted a JSON-escaped title to stderr while its stdout remained audio. The server now captures bounded stderr metadata from that same extraction, rejects a completed download without a title, and sends the title as a percent-encoded `X-Source-Title` header with the unchanged WAV body. The browser decodes that header and uses the title as the editable source name; local-file names are unchanged.

The reported video's API response returned `LOTR The Fellowship of the Ring - Farewell Dear Bilbo` and a valid 44,734,512-byte WAV. The endpoint integration test round-tripped the Unicode title `Björk — 夏` and rejected missing metadata with JSON 502.
