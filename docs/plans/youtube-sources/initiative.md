# YouTube sources

Goal: From each source's Choose audio button, open a popover to choose a local audio file or submit a YouTube URL. Extract audio on the server via yt-dlp and decode it in the existing browser source pipeline.

Non-goals: playlists, video playback, saving YouTube media, changing local-file persistence, or hosting/deployment changes.

Contract: POST `/api/youtube/audio` with JSON `{ "url": "https://www.youtube.com/watch?v=…" }`; success returns `audio/wav` bytes. Failures return JSON `{ "error": "…" }` with a non-2xx status. Only YouTube video URLs are accepted. The server runs yt-dlp and ffmpeg using pipes, with no media file or cache, bounded request/output/runtime. Browser never stores the downloaded audio in IndexedDB; it replaces the source PCM and clears any previously stored local file for that source. Source metadata may retain a generic name/duration for layout restoration; no YouTube URL is stored.

Acceptance: Local import still works via the menu; a valid YouTube video URL loads playable PCM in the selected source and updates its duration; invalid/unavailable URLs expose a recoverable error without replacing existing audio; extracted media is only in transient process/browser memory and not written to persistent storage.

Verification: Server endpoint integration with controlled executables and process termination plus direct HTTP smoke; actual browser popover/local picker, keyboard and URL error recovery; build and tests; live YouTube extraction if external access permits.

Risks: Remote yt-dlp access may fail due to YouTube restrictions. Server needs installed `yt-dlp` and `ffmpeg` binaries in its runtime PATH; document this operational prerequisite. yt-dlp and ffmpeg are subprocesses, not shell commands, and must be bounded/cleaned on aborted requests.
